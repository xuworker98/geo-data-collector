## 1. 网络：先看代理，别先怀疑 Key

常见情况：环境注入了 `http_proxy=127.0.0.1:<端口>` 但该端口无服务，
`urllib` 默默走代理卡到超时，表现与「整网禁网」完全一样，实际直连正常（baidu 200 / 0.15 s）。

```bash
python scripts/config.py
```

输出里看两行：

```
  端口探测 : 不可用 → 已跳过
  实际出网 : 直连
```

`config.http_opener()` 已内置 TCP 端口探测与自动跳过，**不需要手工改环境变量**。
若要显式指定代理：设 `GDC_PROXY`；强制直连传 `http_opener(direct=True)`。

重试全部失败时，`gc_common` 会向 stderr 发 `RuntimeWarning`（`网络请求失败（已重试 N 次）`），
并把原因记进 `gc_common._LAST_NET_ERROR`。看到它说明是**没查成**，不是「图商没有」。

### 1.1 HTTPS 证书校验

默认严格校验。只有身处必须抓包的可信内网排障环境，才临时设：

```powershell
$env:GDC_INSECURE_TLS = "1"     # PowerShell
set GDC_INSECURE_TLS=1          # cmd
```

开启后会打印 `[警告] ... 已关闭 HTTPS 证书校验`。**Key 与地址都在 URL/正文里，
降级等于把凭证暴露给中间人，用完请立刻 unset。**

## 2. Key 问题

### 2.1 Key 类型错（最常见）

必须是**服务端 / Web 服务**类型，不能是浏览器端 JS API Key：

| 源 | 正确类型 |
|---|---|
| 天地图 | Web 服务端 |
| 高德 | Web 服务 |
| 百度 | 服务端 |
| 腾讯 | WebService |

### 2.2 天地图服务端 Key 的 UA

带 Mozilla UA 会直接报 **301013**。与民政部接口**正相反**——民政部接口必须带 Chrome UA，
不带就返回空数据。

### 2.3 配额与熔断

| 源 | 错误码 | 说明 |
|---|---|---|
| 高德 | `10044 USER_DAILY_QUERY_OVER_LIMIT` | **跨自然日不恢复** → 多半是 Key 额度本身低或触发总量/并发限制；换新 Key 比等待有效 |
| 腾讯 | `status=121 此key每日调用量已达到上限` | 广西政务 POI 实测常 0 条，熔断后不影响整体 |
| 天地图 | 日配额 | 按 `daily_cap` 预算，超限当日熔断到次日 0 点 |

熔断状态是**进程内**的，重启进程清零。**禁止用多 Key 轮换突破配额**（违规）。

## 3. 天地图逆地理报 400

- 必须用 `postStr={'lon':x,'lat':y}&type=geocode`
- 写成 `ds={...}` 会被当成**正向**编码 → HTTP 400「keyWord 参数未填写」
- 曾因对 4xx 照样重试，每次白烧 6 s 退避，44 点共 **264 s**（占全套 64%）

**配套铁律：4xx 是永久错，不重试。**

## 4. 天地图「假性失效」：v2/search 坐标字段

`v2/search` 返回的坐标是 **`lonlat` 字符串**「116.1,39.9」，
不是 geocoder 的 `lon` / `lat` 两个字段。

写成 `p["lon"]` 会 `KeyError` 并被引擎静默吞成「无结果」，
表现为**整个天地图源假性失效**——本次真实踩中。

## 5. 编码与乱码

### 5.1 CSV 被 Excel 改成 GBK

交付的 CSV 用户用 Excel 打开再保存，编码会从 `utf-8-sig` 变成 `gbk`；
脚本按 utf-8 读直接 `UnicodeDecodeError: 0xd7`，表现为「文件坏了」。

- 读取：`detect_enc()` 按 `utf-8-sig → gbk → gb18030 → utf-8` 依次试
- 写入：按探测到的原编码回写，另存 utf-8-sig 副本供地图工具导入

### 5.2 Windows 控制台中文乱码

`cmd` 默认代码页 936 时正常；若在 UTF-8 管道里抓输出可能乱码。
显式指定：

```powershell
chcp 65001
$env:PYTHONUTF8=1
python -X utf8 scripts/gc_common.py
```

### 5.3 文件名与路径

中文文件名（如 `模板_采集任务清单.xlsx`）在各平台均可用；
仓库已设 `.gitattributes` 统一 LF，避免 Windows 协作整文件 diff。

## 6. 结果偏差类问题

### 6.1 整体偏移约 0.5 km

**坐标被当成了另一种坐标系。** GCJ-02 与 WGS84 在南宁一带总偏移实测 **510~560 m**
（示例点：西约 478 m / 北约 293 m）。**绝不能把图商原始坐标当 WGS84 直接用。**

```python
from gc_common import detect_crs
detect_crs(points, addrs=addrs)   # 先侦测，交用户拍板，再转换
```

### 6.2 同名地点误匹配

所有查询必须带城市/区县限定。没有城市限定，同名乡镇/村必然误匹配。
模板里「市」「区县」两列就是为此存在。

### 6.3 逆向验真报「乡镇/区县不符」

**先怀疑行政区划变更，再怀疑坐标。** 撤乡设镇、跨区调整会让旧名单整体「验真不过」，
但坐标其实是对的（白沙乡案例：2014 撤乡设镇、2018 划归鱼峰区，坐标全对）。

```python
import adminchain
adminchain.resolve_chain(city="柳州市", area="柳江区", town="白沙乡")
```

### 6.4 自然村查不到 / 查到的是行政村

自然村在地名注记层，`place` 类接口只查 POI 库。要查必须用 `inputtips`，
且**必须用裸村名**（加区划前缀反而查不到）。
规则见 [`../references/自然村采集规则.md`](../references/自然村采集规则.md) R19/R21。

## 7. 输出与依赖问题

### 7.1 输出是 CSV 而不是 xlsx

`openpyxl` 未安装 → 走了第三级降级。装依赖即可：

```bash
pip install openpyxl
```

降级产物列名与内容完全一致，只是载体不同，不影响验收。

### 7.2 读取用户 `.xlsx` 报「需要 openpyxl」

读取 Excel 输入必须装 `openpyxl`；纯坐标转换/区划查询不需要。

## 8. 区划缓存问题

### 8.1 `regions.py --selftest` 报 FAIL「民政部缓存 未找到」

正常现象：新环境没有缓存。首次使用应**联网抓取**：

```bash
python scripts/regions.py --province 广西 --check
```

只有完全无网环境才用 `--import-mca` 导入。

### 8.2 双套代码错位（村挂错乡镇）

民政部（2025）与统计局（2023）调整节奏不同，直接按 9 位码把村挂到乡镇会系统性错位
（广西实测 105 个街镇对不上）。对齐策略三级：L1 码命中 → L2（区县码, 乡镇名）复合键
→ L3 归 orphan（保留区县归属，不编造乡镇）。**绝不硬塞。**
