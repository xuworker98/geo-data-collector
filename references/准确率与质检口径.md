## 一、分场景分级承诺（不虚标 95%）

用户要求 95%，但**政务网点类实测上限 85.4%**。因此按场景分级承诺，
**不允许对做不到 95% 的场景宣称 95%**：

| 场景 | 承诺 ≤100 m 达标率 | 依据 |
|---|---|---|
| 坐标转换 / 纠偏 | **≥99%** | 纯算法，迭代逆解误差 <1 m，黄金向量验证，干净环境实测 0.0 m |
| 坐标系侦测 | **不做准确率承诺，只承诺「不自动决断」** | 双向验证 PASS，但区分度依赖地址质量：20 条样本中仅约 40% 能给出区分信号，其余两次逆地理都返回附近 POI（0:0）。低置信必须交用户拍板 |
| 标准门址 → 经纬度（有门牌号） | **≥90%** | 地址路径占比 85%，①级命中 86.1% |
| **政务服务中心 / 派出所 / 政务网点** | **如实标注实测值**（当前 64.9%~77.5%，三源 75.9%） | 最难场景：图商收录整栋楼、专区在楼内 |
| 自然村 / 村民小组 | **不承诺准确率**，只承诺「必填满 + 列候选交用户」 | 官方无编码无坐标，R3/R7 禁止自动破平 |

### 两条硬承诺（对所有场景）

1. **不杜撰**：查不到就是查不到，绝不用邻近点 / 上级行政区中心冒充目标坐标；
2. **不半截交付**：**必填满**，每条必有交代（坐标 或「未命中 + 原因 + 建议动作」），
   绝不只交最确认的几条然后一片留空。

### 唯一合法口径

```
准确率 = 达标条数 ÷ 总条数
```

**留空 / 存疑 / 未命中一律计为不达标。** 不允许换分母（如「只算有坐标的」）来美化数字。

## 二、三条决定成败的实测归因（改任何参数前必读）

| # | 结论 | 数据 |
|---|---|---|
| 1 | **源的数量不是主要瓶颈** | 高德从熔断到恢复，133 条只救回 **1 条**（75.2% → 75.9%） |
| 2 | **单源是头号杀手** | 1 源 55.6% / 2 源 83.3% / 3 源 **79.7%**（3 源反而不如 2 源 → 坐实 R23 同源抄写） |
| 3 | **输入规范性值 14.7 个百分点，但不是全部** | 地址有门牌号 78.7% vs 无门牌号 64.0%。**即使全部规范，最优子集也只有 85.4%** |

> **推论**：不要靠「多接几个源」或「多跑几遍」提准确率。真正的杠杆是
> ① 把单源条目变成多源；② 政务服务中心类专项；③ 让内容判据压过票数（R23 未解）。

**133 条政务网点实测基准（2026-10-23，三源）**：

| 指标 | 值 |
|---|---|
| ≤100 m 达标率 | **75.9%**（101/133） |
| 中位偏差 / P90 | 30 m / 1229 m |
| 单次全量耗时 | 216 s（约 1.6 s/条） |
| 单条平均请求数 | 9.7 次 |
| 最优子集上限（源数≥2 且 有门牌号） | **85.4%** |

**请求数与达标率的取舍**：3 次请求模式 67.7%，全流程 75.9%——
**砍请求数要付 8.2 个百分点**，由使用者按场景取舍（`Job.max_requests` 类预算可配）。

## 三、质检四层漏斗（L0 → L3）

原则：**验真成本 ∝ 风险**，不是验得越多越准。

| 层 | 名称 | 成本 | 覆盖 | 做什么 |
|---|---|---|---|---|
| **L0** | 零成本硬杀筛 | 0 | 100% | 坐标缺失/非数值、越界、完全重复 → 直接判不合格 |
| **L1** | 零成本离群筛 | 0 | 适用组 | 距锚点距离超自适应上界 → 判离群，列入定向复核 |
| **L2** | 定向验真 | 高 | 高风险子集 | 第二/第三源交叉验真、逆向验真归属 |
| **L3** | 抽样监控 | 低 | 按抽样率 | 按 R6 自适应抽检（正常 5% / 放宽 2% / 加严 15%） |

### 判定阈值（`qc.py`）

- 合格：偏差 **≤300 m**
- 存疑：**300~1000 m**（引第三源仲裁）
- 不合格：**>1000 m**
- 距所属行政村中心 **>3000 m** → 定向复核

### L1 的两条重要修正（2026-10-23 实测）

1. **分组粒度必须下沉到区县**。原实现按「地市」分组 + 组内中位数当锚点，
   广西实测富集倍数仅 **0.69×（无效）**。根因：一个地市内县城间距本就 50~200 km
   （桂林自适应上界被撑到 224 km），组内距离分布双峰，**算法再对也没用**。
2. **优先用外部锚点**（区县政府驻地坐标）；无锚点且组内样本 <3 时
   **诚实跳过该组**，不用无效判据误报——宁可不判，不可误判。
3. 当任务结构是「一区县一点」（133 条散布 100+ 区县）时，同组内 1~2 条样本
   无法构成分布，L1 必须**声明不适用并退出**，而不是硬产出反向判据。

### 风险分（`risk_score`）——把验真预算花在刀刃上

| 特征 | 加分 | 依据 |
|---|---|---|
| 支持源数 ≤1 | +3.0 | 单源实测达标率仅 55.6% |
| 支持源数 =2 | +0.5 | — |
| 名称覆盖率 <0.4 | +1.5 | 名称对不上，疑似回退 |
| 地址级别 ∈（乡镇/道路/空） | +1.5 | 只到乡镇或只给路名，精度不足 |

`risk_score ≥ 3.0` → L2 定向验真；其余按 L3 抽样。

## 四、坐标系侦测：`detect_crs()`（双假设反向验证）

```python
from gc_common import detect_crs
r = detect_crs([(lon, lat), ...], addrs=["用户地址", ...], sample_n=10)
# → {"判定": "WGS84"/"GCJ-02"/"无法判定", "置信度": "高/中/低", "样本明细": [...]}
```

原理：假设 A「是 WGS84」直接逆地理；假设 B「是 GCJ-02」先转 WGS84 再逆地理。
两次查询位置相差约 500 m，**谁的逆地理地址与用户地址更吻合，谁就是真实坐标系**。

### 四个已踩过的坑（改代码前必读）

1. **贪婪吞字**：路名正则写成 `{2,8}` 会把「良庆区玉洞大道」吞成「市良庆区玉洞大道」
   → 必须先 `_strip_admin()` 剥掉行政区划前缀（与 R-P9 同类错误）。
2. **空格未归一化**：用户写「33 号」、逆地理回「33号」，不去空格永远不匹配。
3. **判据必须细粒度**：偏移只有 300~600 m，**区县级别两种假设往往相同**，
   必须用路名/门牌比对。
4. **只测一组会自欺**：永远返回 WGS84 的假函数也能在「真值=WGS84」的测试里拿满分，
   必须**双向验证**（同样本转 GCJ-02 后应判 GCJ-02）。已用 20 条样本双向验证 PASS。

**纪律**：侦测结论**必须交用户拍板后再转换**，不得自动执行（误判代价 = 整表偏移 500 m）。

## 五、输入输出规范（三套固定格式，不允许临时发明）

### ① 输入：标准模板（列定义唯一真源：`scripts/export.py: TPL_FIELDS`）

```
任务ID | 任务类型 | 省 | 市 | 区县 | 乡镇 | 关键词 | 中心点经度 | 中心点纬度
 | 半径米 | 名称 | 详细地址 | 参考经度 | 参考纬度 | 待查列 | 备注
```

- 任务类型取值**只能**是：政府驻地 / POI周边 / POI区内分类 / POI关键词 / 地址转坐标 / 坐标转换
- 生成模板：`python scripts/export.py --template`
- 城市限定必带；详细地址尽量写到门牌号（实测有无门牌号差 14.7 个百分点）

### ② 输出：明细列（`OUT_FIELDS`，六表共用）

```
序号 | 任务ID | 名称 | 所属地市 | 所属区县 | 详细地址
 | 经度_WGS84 | 纬度_WGS84 | 经度_GCJ02 | 纬度_GCJ02
 | 来源源 | 支持源数 | 命中方式 | 地址级别 | 名称覆盖率 | 门牌分
 | 置信度 | 质检状态 | 存疑原因 | 建议动作
```

- `经度_GCJ02 / 纬度_GCJ02` **必带**：供用户在高德地图直接取点核对（R10 闭环验证法）
- `质检状态` 只有三种：**通过 / 存疑 / 未命中**，禁止再发明第四种
- 六表：地市表 / 区县表 / 乡镇表 / 明细清单 / 汇总表 / 校验表
- 输出三级降级链：openpyxl → 纯标准库 OOXML（真 `.xlsx`）→ CSV，三种形态列名与内容完全一致

### ③ 质检报告：五段固定结构（`write_qc_report()` 自动生成 Markdown）

```
① 任务概览   任务ID / 模块 / 条数 / 起止 / 版本
② 计划对账   请求数 计划 vs 实际；耗时 计划 vs 实际；分几批
③ 质量结论   主口径准确率（分母=总条数）+ 通过/存疑/未命中 + 中位/P90 偏差
④ 异常清单   逐条：名称 / 偏差 / 问题归类 / 已采取动作
⑤ 遗留与建议 未解决项 + 需用户人工确认清单（附 GCJ-02 坐标供核对）
```

**写作纪律**：存疑文本不许堆砌。单条存疑曾塞进几十条「候选簇N距村委 XXXX m > 上界」，
把真正要人看的信息全淹了；应压成一条：
`自适应上界 5577 m，剔出 7 个离群同名簇（最远 23576 m）`。

## 六、向用户汇报准确率的模板

```
主口径：达标 X 条 ÷ 总 Y 条 = Z%（留空/存疑/未命中均计入不达标）
通过 / 存疑 / 未命中：a / b / c
偏差分布：中位 xx m，P90 xxx m
分场景承诺对照：本批属「政务网点」场景，承诺 ≥90%，本批 Z%
遗留：需人工确认 N 条（附 GCJ-02 坐标）
```

**不允许**把「只算已命中条目」的比例当准确率汇报。
